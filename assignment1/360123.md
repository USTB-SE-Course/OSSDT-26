## 1. 项目用途与选择原因

我选择 Laravel，是因为我的电商项目就用它来写后台。以新增商品为例，我在 React 页面填写商品名称、价格和分类，点击保存后，前端把这些数据发给 Laravel。后端要先检查价格等字段是否符合要求，再把商品写入 MySQL，最后告诉前端保存是否成功。做这个功能时，我能直接看到路由、数据校验和数据库操作各自解决了什么问题。

Laravel 是面向 PHP 开发者的 Web 框架。开发者可以用它写网站，也可以像我这样，只用它提供接口，让 React 负责显示页面。我调研的 `laravel/framework` 仓库存放框架本身的代码。平时我关心的是自己的商品接口能不能工作，这次我更想知道，我用到的校验和数据库功能是谁在改、改了什么。[项目 README](https://github.com/laravel/framework/blob/v13.43.0/README.md)

## 2. 开源许可证

Laravel Framework 使用 MIT 许可证，允许使用、修改和分发框架，也允许商业使用。其中有一项具体义务：软件的副本或包含其实质性部分的副本，都要保留原版权声明和许可声明。例如，如果我把包含 Laravel 框架源码的电商后台打包交给同学，就应该把框架自带的许可证文件一起保留，这样收到代码的人也能看到原作者和使用条件。[许可证原文](https://github.com/laravel/framework/blob/v13.43.0/LICENSE.md)

## 3. 维护与活跃情况

**版本发布。** 2026 年 11 月 17 日，项目发布了 v13.43.0。其中一项改动和批量表单有关。假设一次提交很多行商品，每一行都要比较两个字段，校验器可能反复查找同一批字段。这次改动让后续校验可以复用第一次查找时建立的集合。发布说明列出了对应的 PR，读者可以从版本号一路查到具体原因。[版本记录](https://github.com/laravel/framework/releases/tag/v13.43.0) · [改动说明 #62464](https://github.com/laravel/framework/pull/62464)

**合并与测试。** 11 月 19 日，PR #62423 合并进了 13.x 分支。它让开发者设置一个时间上限，数据库事务结束后，如果耗时超过这个值，就可以记录一条日志。这个 PR 还加了测试：很快结束的事务不会触发回调，耗时超过设定值的嵌套事务只触发一次。这两条记录说明，11 月中旬既有改进交付给用户，也有带测试的新代码进入开发分支。[PR #62423](https://github.com/laravel/framework/pull/62423) · [测试改动](https://github.com/laravel/framework/pull/62423/files)

如果以后在项目里遇到框架问题，我可以先写一个能重现问题的小例子。按 Laravel 的贡献指南，提交修复 PR 时，应说明问题出现的条件、预期结果和修复方法，让维护者能够验证改动。[贡献指南](https://laravel.com/docs/13.x/contributions#bug-reports)
