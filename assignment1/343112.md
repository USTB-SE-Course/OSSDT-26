## 1. 项目用途与选择原因

LiteNetLib 是一个面向 .NET 开发者的轻量级 UDP 网络库，适用于用 C# 或 Unity 开发多人游戏的场景。由于 UDP 本身没有可靠送达和按序交付的保证，因此 LiteNetLib 通过提供连接管理、消息读写和多种投递方式，让开发者可以按消息的用途选择可靠有序或不可靠等模式。具体见 [项目 README](https://github.com/RevenantX/LiteNetLib/blob/a3d7d445085cf27083a1fbd79e10890d714fbe9b/README.md)

我在 TankBattleOnline 中用 C# 和 TCP 做过局域网联机，需要在主机和客户端之间同步房间和对局状态。我想了解，如果改用 UDP，哪些消息值得等待重传。比如，开局指令需要可靠送达，高频位置更新则可能很快被下一条消息覆盖。LiteNetLib 把这些选择放在发送接口里，正好可以用我熟悉的联机场景理解它的设计。[TankBattleOnline](https://github.com/TouchingFish444/TankBattleOnline)

本次还在 .NET 8 环境下借助 Codex 运行了仓库自带的 `PacketProcessorExample`。客户端连上本机服务端后，把三组坐标和其他字段打包成一条消息，再用 `ReliableOrdered` 发送。服务端在接收回调中解析数据，终端输出 `List count: 3`，随后打印的三组坐标与客户端发送的值一致。这次运行验证了客户端和服务端能够按同一结构读写数据。实际局域网下的延迟和丢包表现还需要另外测试。[示例源码](https://github.com/RevenantX/LiteNetLib/blob/a3d7d445085cf27083a1fbd79e10890d714fbe9b/LibSample/PacketProcessorExample.cs)

## 2. 开源许可证

LiteNetLib 采用 MIT 许可证，允许使用、修改和再分发。许可证要求软件的所有副本或实质性部分都附有原版权声明和许可声明。比如，将 LiteNetLib 的源码纳入自己的游戏并随游戏分发时，应在分发材料中保留这两项声明。[许可证原文](https://github.com/RevenantX/LiteNetLib/blob/a3d7d445085cf27083a1fbd79e10890d714fbe9b/LICENSE.txt)
