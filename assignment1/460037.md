## 1. 项目用途与选择原因
PyGithub 是一个用于访问 GitHub REST API 的 Python 库。开发者可以在 Python 程序中调用它来管理仓库、用户资料和组织等 GitHub 资源，不必自己手写每一个 API 请求。它的主要用户是需要自动化操作 GitHub 的 Python 开发者，例如编写仓库统计脚本、CI 辅助工具或自动化机器人的人。通过 `pip install PyGithub` 即可安装，并在代码中使用 `from github import Github` 调用。
选择原因：
1. 与课程内容直接相关。课程第3讲（项目依赖管理）用 PyGithub 作为示例，说明如何通过 PyPI 查找第三方软件包、声明依赖，并用 uv 管理环境。课程项目也要求获取 GitHub 仓库的 Star 数和 Fork 数，PyGithub 正好能实现这一功能。
2. 我对它感兴趣。我是 Python 初学者，想知道课上用到的这个库背后是什么样的开源项目，由谁维护、许可证是什么、现在是否还在更新。
3. 它的许可证与我之前接触的 MIT 不同（LGPL-3.0），可以借此机会学习不同许可证在使用和再分发上的差别。
## 2. 开源许可证
PyGithub 使用 **LGPL-3.0**（GNU Lesser General Public License，第3版）。仓库中同时包含 `COPYING.LESSER`（LGPL-3.0 文本）和 `COPYING`（GPL-3.0 文本）两个文件，LGPL-3.0 是在 GPL-3.0 基础上增加了额外许可。
许可证文件链接：https://github.com/PyGithub/PyGithub/blob/main/COPYING.LESSER
我需要注意的一项义务（根据我阅读许可证文本后的理解）：如果我修改了 PyGithub 自身的源码，并把修改后的版本分发给别人，就需要继续以 LGPL-3.0 授权，并提供相应的源码。而如果我只是把 PyGithub 作为依赖库来调用（例如在课程项目中通过 `pip` 或 `uv` 安装使用），我自己的程序不一定要采用 LGPL，但仍需遵守许可证对保留版权和许可声明等方面的要求。这一点与 MIT 许可证不同：MIT 主要要求在复制或再分发时保留版权声明和许可声明，对修改后的代码没有要求继续开源。
以上理解来自我对 LGPL-3.0 文本（如其中关于修改版本和组合作品的条款）的阅读，不构成法律意见；实际使用中如有商业分发等情况，需要再仔细核对条款。
