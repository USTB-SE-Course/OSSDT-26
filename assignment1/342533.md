## 1. 项目用途与选择原因

Haystack 是由 deepset 团队主导的 Python 开源框架，用于把文档检索、结果排序和大模型生成等步骤组织成可组合的 Pipeline，构建语义搜索、RAG（检索增强生成）和多智能体应用。典型用法是先把私有文档解析、切分并向量化后写入向量库，查询时检索出相关片段再交给大语言模型生成答案，从而缓解模型知识过时和凭空编造的问题。它的目标用户是需要搭建 RAG 系统或企业知识库的 Python 开发者与团队；deepset 同时提供付费托管平台，而框架本身以开源社区版发布。

我选择它的原因有三个：一是我关注 RAG 方向，Haystack 在这一领域的模块边界比较清楚，检索器、排序器、生成器各自独立，便于理解；二是它用 Python 编写，与课程以 Python 开源软件开发为主线一致；三是它的贡献规范和许可证说明完整，适合作为观察开源协作流程的样本。

## 2. 开源许可证

项目采用 Apache License 2.0，许可证文件见 https://github.com/deepset-ai/haystack/blob/main/LICENSE 。

使用时需要注意的义务是：修改并再分发代码时，必须保留原有版权与许可证声明，并在被改动的文件中注明已修改；再分发时要附带许可证副本。我核对了仓库根目录，没有单独的 NOTICE 文件，因此不需要额外分发通知文件。另外，Apache-2.0 不授予商标使用权，不能以 deepset 或 Haystack 的名义暗示官方背书。仓库中的 license-header.txt 和 licenserc.toml 也说明新增源文件需要带上 Apache 声明头。还有一点：向项目贡献代码需签署 CLA，签署入口见 https://cla-assistant.io/deepset-ai/haystack 。

### 参与方式

仓库的 CONTRIBUTING.md（https://github.com/deepset-ai/haystack/blob/main/CONTRIBUTING.md ）给出了一条完整路径：先挑选带 good first issue 或 "Contributions wanted!" 标签的 Issue（调研时这两类标签暂时没有开放条目），fork 仓库并安装 pre-commit，用 hatch 运行单元测试和格式检查；PR 需使用 conventional commit 标题、填写 PR 模板、在 releasenotes/notes 下补 release note，并签署 CLA；完全由 AI 生成的 PR 需要在描述中声明。日常提问还可以使用项目的 Discord 频道。
