## 1. 项目用途与选择原因

Visual Studio Code 是一个跨平台的代码编辑器。它的目标是把代码编辑、跳转与代码理解、轻量调试和扩展能力放在同一个工具里，让开发者不必在编辑器、浏览器和命令行之间来回切换；同时它支持 Windows、macOS 和 Linux，并通过丰富的扩展适配几乎各种语言和工具链。因此它的用户既包括日常写应用的专业程序员，也包括刚开始学编程、需要一个简单的编辑与调试环境的学生，还包括为它编写扩展的第三方开发者。

需要说明的是，本次调研的仓库是 Code-OSS，即微软与社区共同开发 Visual Studio Code 产品的地方；仓库 README 明确说明，带微软定制的官方发行版与开源版本并不完全相同，路线图和迭代计划也都公开在仓库 Wiki 中。[^1]

我选择这个项目有两个原因。第一，我自己写代码时就在使用 VS Code，对它的界面和基本功能有直观认识，读仓库时不会连它在解决什么问题都搞不清楚。第二，它的仓库规模很大、开发流程完全公开（提交、版本发布、Issue 指派和里程碑都能查到），适合练习"从仓库而非宣传材料了解一个项目"。本次作业只做调研，我没有安装运行该项目，也没有向它提交代码。

## 2. 开源许可证

许可证名称：**MIT License**（SPDX 标识：MIT）。许可证文件：<https://github.com/microsoft/vscode/blob/main/LICENSE.txt> 。文件开头写有 "Copyright (c) 2015 - present Microsoft Corporation"。

需要特别注意的一项义务是：在复制、修改、合并、发布、分发、再许可或销售本软件时，必须把上述版权声明和许可声明包含在软件的所有副本或实质性部分中。换言之，基于它做二次分发时，不能把原许可声明删掉；许可证同时声明软件按"原样"提供，不附带任何明示或暗示的担保。[^2]

另一个容易混淆的点：README 说明MIT许可适用于本仓库源码（Code - OSS），而微软官方发行的 Visual Studio Code 产品还包含微软特有的定制，受另一份传统产品许可约束。所以写报告时说"这个仓库是 MIT 许可"是准确的，但不应把官方发行版的一切都等同于 MIT。

## 3. 维护与活跃情况

我从以下三个方面观察，证据均来自调研当天（2026-11-28）查到的公开记录：

1. **提交（Commit）**：main 分支当天的提交非常密集。例如提交 `dcf30e9`（作者日期 2026-11-28 05:01 UTC）和 `acc56cf`（同日 05:01 UTC），均可点开查看；最新五条提交的作者日期都集中在 2026-11-28。[^3] 这直接说明代码在持续改动。
2. **版本发布（Release）**：1.148.0 于 2026-11-25 发布，1.147.0 于 2026-11-18 发布，1.146.0 于 2026-11-11 发布，大体保持每周一个稳定版本的节奏，并且每版都附带官方更新说明链接。[^4] README 也称产品按月更新，实际还有补丁版本。
3. **Issue 与 PR 的处理**：开放 Issue #350821（"ChatLanguageModels.json not working"）在 2026-11-28 仍有更新，并已指派给维护者；PR #350806 关联里程碑 "1.149.0"，同一天仍在更新。[^5] 这不仅是"有人提问题"，还能看到指派和版本规划等后续动作。

**判断**：这是一个维护非常活跃、流程公开的项目，社区反馈进入版本里程碑， releases 节奏稳定。我没有用 Star 数量作为判断依据。

**局限**：以上只是某一天的快照，不能说明长期趋势；仓库开放的 Issue 数量约 2.2 万，既反映社区参与度高，也可能意味着反馈积压；我未统计贡献者分布，因此无法判断维护是否过度依赖少数人。
