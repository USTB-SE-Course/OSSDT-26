## 4. Git命令记录

以下命令按主要操作顺序整理。创建公开仓库、发起与合并 PR 在 GitHub 网页完成。

| 命令 | 用途与关键结果 |
| --- | --- |
| `git clone https://github.com/JStriker7/git-practice.git git-practice-a2` | 将练习仓库克隆到本地目录。 |
| `git switch -c feature/intro` | 创建并切换到功能分支。 |
| `git diff -- README.md` | 检查仓库说明文件的未暂存改动。 |
| `git add -- README.md`、`git diff --cached -- README.md` | 暂存正确的 README，并检查此次提交会包含的内容。 |
| `git commit -m "说明仓库用途"` | 创建第一条提交 `f70dfd3`。 |
| `git add -- practice.md`、`git commit -m "添加协作练习文件"` | 在改正练习文件名后暂存并提交，得到 `659d8f1`。 |
| `git log -2 --oneline` | 确认两次有效提交都在功能分支的历史里。 |
| `git push -u origin feature/intro` | 向 GitHub 推送功能分支并设置跟踪关系。 |
| `git switch main`、`git pull --ff-only`、`git log -4 --oneline` | 网页合并个人 PR 后同步本地默认分支，并确认两次功能提交都已合入。第一次误写成 `git pull --ff only`，Git 把 `only` 当成远程仓库名。改为单个选项 `--ff-only` 后拉取成功。 |
| `git add -- practice.md`、`git commit -m "补充合并冲突练习目标"`、`git push origin main` | 在我的 `main` 提交同一行的另一种改法，并推送 `dc5aae4`。 |
| `git fetch origin`、`git fetch origin pull/2/head` | 更新远程引用，将协作 PR 的来源提交取到 `FETCH_HEAD`。 |
| `git switch -c resolve/pr-2 FETCH_HEAD` | 从协作 PR 的提交创建并切换到本地冲突处理分支。 |
| `git merge origin/main`、`git status` | 将最新的默认分支合入处理分支。Git 在 `practice.md` 报告内容冲突。 |
| `git add -- practice.md`、`git commit -m "解决 practice.md 的合并冲突"` | 编辑并保存最终内容后，标记文件已解决，创建解决提交 `d508617`。 |
| `git push https://github.com/mwu381690-debug/jstriker7-git-practice.git HEAD:collaboration/goal` | 把解决提交推回同学 Fork 的原分支，更新原协作 PR。 |
| `git switch main`、`git pull --ff-only` | 网页合并协作 PR 后，将本地 `main` 同步到 `c19b1ea`。 |
| `Get-Content -Encoding UTF8 .\practice.md` | 在 PowerShell 中读取合并后的文件，确认最终句子同时包含双方的练习目标。 |
