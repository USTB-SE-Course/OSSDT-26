## 3. 冲突产生与解决

我方曾通过 [PR #3](https://github.com/TouchingFish444/TankBattleOnline/pull/3) 细化 `practice.md` 中记录两端同步结果的要求。由于同学的 PR 改的是 HUD 代码，这两项改动可以自动合并。因此实际选择了双方都在修改的 `Controls/GameHudPanel.cs` 进行冲突练习。

冲突发生在 `GameHudPanel.Bind` 方法内，位于帧率显示与角色说明之间。我方在这里设置倒计时文字，同学在同一位置设置倒计时和血量的颜色。PR #4 合并后，Codex 按我的指示在本地检出同学的 PR 分支，并执行 `git merge --no-edit origin/main`。终端实际输出如下：

```text
Auto-merging Controls/GameHudPanel.cs
CONFLICT (content): Merge conflict in Controls/GameHudPanel.cs
Automatic merge failed; fix conflicts and then commit the result.
```

`git status --short` 显示 `UU Controls/GameHudPanel.cs`。`practice.md` 由 Git 自动合并。

冲突块中保留了我方的倒计时文字和同学的颜色提醒。回合期间显示分:秒，结束时显示「本局结束」。剩余时间不超过 10 秒时，倒计时标红。当前玩家存活且血量不超过 25% 时，血量标红。回合结束后，两项颜色恢复正常。合并时也删除了重复的标签赋值，避免多个位置更新同一项显示。保留两项改动的理由是，玩家需要读出剩余时间，也需要快速识别时间或血量告急。

解决提交为 [`b6dfe8c`](https://github.com/TouchingFish444/TankBattleOnline/commit/b6dfe8c17d8506dcf03d3c85fe990008478bd2ad)。它的两个父提交是同学的 `884d94d` 和我方已合入 `main` 的 `b74e3eb`。解决提交推回同学原分支后，[PR #2](https://github.com/TouchingFish444/TankBattleOnline/pull/2) 合入 `main`，最终合并提交为 [`15574d0`](https://github.com/TouchingFish444/TankBattleOnline/commit/15574d012889cd69ade44bc72a96b00e7757f5f1)。本地 `main` 已同步到该提交。

冲突触发、文件编辑、解决提交、推送和最终合并由 Codex 按我的指示执行。作业要求学生亲自处理冲突，因此这次记录如实保留实际执行者，本人操作证据待补充。

## 4. Git命令记录

1. **克隆仓库并创建分支。** 在课程仓库根目录重新克隆项目，随后在 TankBattleOnline 目录从 `main` 创建功能分支。创建分支时 `main` 指向 `9dacf62`。

   ```powershell
   git clone -- https://github.com/TouchingFish444/TankBattleOnline.git assignment2/TankBattleOnline
   git switch -c feature/join-by-room-address
   git status --short --branch
   ```

2. **检查改动并分次提交。** 先查看变更范围，再按代码、初版测试清单和使用说明分别暂存。每次提交前用 `git diff --cached --check` 检查暂存内容。

   ```powershell
   git diff --stat
   git add -- Controls/RoomInfoPanel.cs Forms/GameForm.Room.cs
   git diff --cached --check
   git commit -m "Support joining with an IPv4 address and port"
   git add -- practice.md
   git diff --cached --check
   git commit -m "Add LAN multiplayer practice checklist"
   git add -- README.md practice.md
   git diff --cached --check
   git commit -m "Document and verify complete room address entry"
   ```

3. **检查分支差异、推送并创建 PR。** 与远端 `main` 比较后确认变更仅涉及两个代码文件、README 和 `practice.md`。推送时设置远端跟踪分支，然后使用 GitHub CLI 创建个人 PR，说明变更及验证结果。

   ```powershell
   git diff --check origin/main...HEAD
   git diff --name-status origin/main...HEAD
   git push --set-upstream origin feature/join-by-room-address
   ```

   创建时使用 `gh pr create`，指定 `--repo TouchingFish444/TankBattleOnline --base main --head feature/join-by-room-address`，并通过 `--title` 和 `--body-file` 提供标题和说明。

4. **在 GitHub 合并后同步本地分支。** 回到本地 `main`，通过快进同步 GitHub 上的合并结果。日志首条为 `dcd63a1`，随后是功能分支的三次提交。

   ```powershell
   git switch main
   git pull --ff-only origin main
   git log -4 --oneline
   ```

5. **检查同学的 PR。** 检查来源分支、变更范围和初始合并状态，再在临时副本构建初版提交 `95a6234`。初版构建报 `CS0136`。

   ```powershell
   gh pr view 2 --repo TouchingFish444/TankBattleOnline
   gh pr diff 2 --repo TouchingFish444/TankBattleOnline --patch
   ```

6. **在我方分支更新验收说明。** 从当时的 `main` 建立文档分支，提交并推送 `practice.md` 的单行修改。通过 GitHub CLI 创建、检查并合并 PR #3，随后将本地 `main` 快进到 `3f330ac`。

   ```powershell
   git switch -c docs/record-lan-sync-results main
   git diff -- practice.md
   git add -- practice.md
   git commit -m "Record LAN sync results from both players"
   git push --set-upstream origin docs/record-lan-sync-results
   gh pr create --repo TouchingFish444/TankBattleOnline --base main --head docs/record-lan-sync-results --title '补充联机同步结果的记录要求' --body '更新 practice.md 的联机验收项，要求分别记录主机端和客户端的同步结果，并标明异常出现在哪一端。已检查 Git 差异。'
   gh pr diff 3 --repo TouchingFish444/TankBattleOnline
   gh pr merge 3 --repo TouchingFish444/TankBattleOnline --merge --match-head-commit 263ea0cb0dd39771b4cfe66748903400439aa2bd
   git switch main
   git pull --ff-only origin main
   ```

7. **复核同学更新后的 PR。** 对照 PR #2 的提交与文件差异，在临时副本获取同学的更新，检出 `884d94d` 并重新进行 Release 构建。构建通过。对照当前 `main`，确认双方的改动仍分别位于 HUD 代码和练习清单。

8. **提交倒计时显示改动并合并 PR #4。** 从 `main` 建立我方 HUD 分支，修改 `Controls/GameHudPanel.cs`。构建通过后提交、推送并用 GitHub CLI 创建 PR #4。核对文件差异后合并，随后获取更新后的 `origin/main`，其提交为 `b74e3eb`。

   ```powershell
   git switch -c feature/hud-countdown-format main
   dotnet build .\TankBattleOnline.csproj -c Release --nologo
   git add -- Controls/GameHudPanel.cs
   git diff --cached --check
   git commit -m "Show the HUD countdown as minutes and seconds"
   git push --set-upstream origin feature/hud-countdown-format
   gh pr create --repo TouchingFish444/TankBattleOnline --base main --head feature/hud-countdown-format --title '将 HUD 倒计时显示为分:秒' --body '回合进行时以分:秒显示剩余时间，回合结束时显示「本局结束」。Release 构建通过。'
   gh pr diff 4 --repo TouchingFish444/TankBattleOnline
   gh pr merge 4 --repo TouchingFish444/TankBattleOnline --merge --match-head-commit 01f6a84a9d30e4a8eba78c68242d378219264dba
   git fetch origin main
   ```

9. **检出协作分支并触发真实冲突。** 将 PR #2 检出到本地解决分支，确认共同基础后合入最新 `main`。合并以退出码 1 返回，检查确认只有 HUD 文件未合并。

   ```powershell
   gh pr checkout 2 --repo TouchingFish444/TankBattleOnline --branch resolve/hud-countdown-warning
   git merge-base HEAD origin/main
   git merge --no-edit origin/main
   git status --short
   git diff --name-only --diff-filter=U
   git diff --cc -- Controls/GameHudPanel.cs
   ```

10. **解决冲突、验证和更新原 PR。** 编辑 HUD 文件后，Release 构建通过，7 项 HUD 状态检查全部通过。暂存后确认只剩 HUD 文件相对 `origin/main` 有改动，提交解决结果并推回同学的 Fork。检查 PR #2 的差异后合并，最后更新本地 `main`。使用 `git diff --exit-code` 确认最终 `main` 的文件内容与已经验证的解决提交一致。

    ```powershell
    dotnet build .\TankBattleOnline.csproj -c Release --nologo
    git add -- Controls/GameHudPanel.cs
    git diff --cached --check
    git diff --cached --name-status origin/main
    git commit -m "Resolve HUD countdown and warning merge conflict"
    git log -1 --format='%H %P %s'
    git push https://github.com/Lsac12/TankBattleOnline.git HEAD:refs/heads/feature/hud-low-health-warning
    gh pr diff 2 --repo TouchingFish444/TankBattleOnline
    gh pr merge 2 --repo TouchingFish444/TankBattleOnline --merge --match-head-commit b6dfe8c17d8506dcf03d3c85fe990008478bd2ad
    git switch main
    git pull --ff-only origin main
    git diff --exit-code b6dfe8c..main
    ```
