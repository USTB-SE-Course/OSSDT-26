## 3. 冲突产生与解决

- **共同基础版本及两侧修改的 Commit 链接**：
  - 共同基础：[171cc9c](https://github.com/lbl-ustb/git-practice/commit/171cc9c523b2bc16fcab8062adc59cc10ab24c37)，第 25 行为 `协作说明：待补充`
  - 协作分支一侧（版本 A）：[69055b1](https://github.com/lbl-ustb/git-practice/commit/69055b17355f413716011fe6dc00bce632b3e849)，`Sandm-lbl/git-practice:collab/update-note`
  - 默认分支一侧（版本 B）：[40bf36f](https://github.com/lbl-ustb/git-practice/commit/40bf36f49307d866b6af3c8d83bba420fb9a8805)，`main`
- **冲突发生的文件、位置及原因**：`practice.md` 第 25 行（“协作留言”一节）。两个分支都从 171cc9c 出发，修改了同一行的不同内容，Git 无法自动判断应保留哪一版。
- **Git 冲突提示或冲突内容**：在本地协作分支上执行 `git merge origin/main`，输出如下：
  ```text
  Auto-merging practice.md
  CONFLICT (content): Merge conflict in practice.md
  Automatic merge failed; fix conflicts and then commit the result.
  ```
  `git status` 显示 `both modified: practice.md`，文件中的冲突标记为：
  ```text
  <<<<<<< HEAD
  协作说明：由 Sandm-lbl Fork 本仓库并修改此行（版本 A）
  =======
  协作说明：本仓库由 lbl-ustb 维护，欢迎通过 Fork + PR 参与（版本 B）
  >>>>>>> origin/main
  ```
- **解决步骤、最终内容及选择理由**：
  1. 删除 `<<<<<<<`、`=======`、`>>>>>>>` 三处冲突标记，把两侧内容合成一行；
  2. 用 `grep` 确认文件中没有残留冲突标记，用 `git diff` 查看合并差异；
  3. `git add practice.md`，`git commit --no-edit` 生成合并提交；
  4. `git push sandm HEAD:collab/update-note`，推送到 PR #2 的源分支（PR 开启了“允许维护者编辑”），PR #2 自动更新。
  最终内容为：
  ```text
  协作说明：本仓库由 lbl-ustb 维护，欢迎通过 Fork + PR 参与；Sandm-lbl 曾通过 PR #2 修改本行，合并冲突时保留了双方信息。
  ```
  选择理由：版本 B 说明了仓库维护者和参与方式，版本 A 记录了这一行曾经由 PR 修改，两者表达的信息不重复。只保留任何一侧都会丢失另一侧的信息，所以选择合并两者，同时保持“协作说明”仍是一行。
- **解决冲突的 Commit 链接**：[eea2a40](https://github.com/lbl-ustb/git-practice/commit/eea2a401f89ae121998626c292c7b7e3afcbcc4b) `Merge remote-tracking branch 'origin/main' into collab/update-note`
