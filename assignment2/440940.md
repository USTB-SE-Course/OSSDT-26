  - 协作分支一侧：[cddf85b](https://github.com/GuaBa666/git-practice/commit/cddf85b88a4a1de867b79a9eaca73dba256e75f2)，保留这一行并在其后追加三张图片引用。
- **冲突文件、位置及原因**：`practice.md` 第 1 行所在区域。基础版本中整个文件只有一行，两个分支的改动都覆盖这同一行区间——一侧把该行替换为文章，另一侧在同一行之后扩展内容，Git 无法确定同一行的最终形态，只能把整段交给人工判断。
- **Git 冲突提示**：

```bash
$ git merge origin/master
Auto-merging practice.md
CONFLICT (content): Merge conflict in practice.md
Automatic merge failed; fix conflicts and then commit the result.
```

- 文件中的冲突内容：

```
<<<<<<< HEAD
Hello, world!
![](image/minecraft-git-multibranch.png)

![](image/minecraft-git-conflict.png)

![](image/minecraft-git-graph.png)
=======
## 用 Minecraft 类比理解 Git

可以把 `main` 想成大家的 Minecraft 主世界……
>>>>>>> origin/master
```

- **解决步骤**：
  1. 在创建冲突处理分支 `fix/pr1`（跟踪同学的 `feat/image`）上把 `origin/master` 合并进分支触发冲突后，读取冲突标记，确认两侧内容并不互斥；
  2. 保留 `origin/master` 一侧的整篇文章作为正文，把 `HEAD` 一侧的三张图片引用按语义插入正文对应位置，删除 `<<<<<<<`、`=======`、`>>>>>>>` 三行标记
  3. 执行 `git add practice.md` 与 `git commit`，再把合并结果推送到发起 PR 的分支 `feat/image`，使原 PR 更新。
- **最终内容**：`practice.md` 共 58 行，文章完整；三张图片位于各自的小节中。
- **选择理由**：文章是默认分支已被合并的正式内容，属于该文件的正文主体；三张图片是协作者新增、且正文确实需要的示意图。两侧内容是“正文”与“配图”的互补关系，因此取并集。
- **解决冲突的 Commit**：[34373c9](https://github.com/GuaBa666/git-practice/commit/34373c931c404e33a77b7ee49cee3564a22e6777)，提交消息为 `Merge remote-tracking branch 'origin/master' into fix/pr1`，父提交为 `cddf85b` 与 `d0f2035`。

## 4. Git命令记录

### 步骤 0：仓库初始化与首次推送

```bash
git remote add origin git@github.com:LiquMouse/git-practice.git
git add . && git commit -m "Initial commit"
git add . && git commit -m "Add README"
git push --set-upstream origin master
```

结果：`master` 产生 `1022b3c`（Initial commit）与 `8524804`（Add README）；`practice.md` 内容为 `Hello, world!`，`README.md` 说明仓库为课程作业练习用。

### 步骤 1：创建功能分支并完成两次提交

```bash
git checkout -b feat/intro 
vim practice.md                   # 写入标题与总述段
git add practice.md
git commit -m "feature: Add introduction"
vim practice.md                   # 补充三个小节与示例命令
git add practice.md
git commit -m "feature: Add details"
git push -u origin HEAD
```

### 步骤 2：在 GitHub 网页发起并合并 PR #2

网页操作：打开 `feat/intro` → `master` 的 PR，标题 `feat/intro`、说明“添加用Minecraft类比Git的描述”；在 Files changed 中核对两个提交的差异后点击 Merge pull request（merge commit），得到 `d0f2035`。

### 步骤 3：同步本地默认分支

```bash
git checkout master
git pull
```

### 步骤 4：接入同学的协作分支

```bash
git remote add guaba git@github.com:GuaBa666/git-practice.git
git fetch guaba
```

### 步骤 5：合并默认分支，触发并解决冲突

```bash
git switch -c fix/pr1 guaba/feat/image   # 基于同学分支创建本地处理分支
git merge origin/master                  # 触发冲突
vim practice.md                          # 保留文章，按小节插入三处图片引用，删除冲突标记
git add practice.md
git commit
git push guaba HEAD:feat/image
```

结果：`34373c9` 推送到 `feat/image`，PR #1 的提交列表更新为 `cddf85b` + `34373c9`，冲突消除。

### 步骤 6：网页合并 PR #1 并核查

网页操作：打开 PR #1 → Merge pull request（merge commit），`master` 得到 `5166070`。

```bash
git switch master
git pull
```

结果：`master` 的 `practice.md` 与 `image/` 下三个文件与本地工作区一致。
